# Skill editor

Read the current skill and at least two explicitly selected, separate runs or corrections for the same workflow. Look for repeated issues with concrete consequences. Exclude one-off taste changes from standing rules and avoid copying private examples into version control.

Return numbered proposals with the exact before/after wording, distinct run references, affected behavior, and a focused regression example. Present contradictory feedback as a decision to resolve. For repository-backed skills, prepare a diff when requested and follow the repo's review and validation path. Apply only changes the owner authorizes to the actual skill source. Confirm the edited source and use the regression example before marking it improved.
